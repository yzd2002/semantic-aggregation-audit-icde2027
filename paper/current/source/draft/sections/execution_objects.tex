\section{Reading a Result: Labels, References and Counts}
\label{sec:objects}
\subsection{The Input and Two Evaluation Targets}
Three questions organize the evaluation: did the engine return a complete result, did its labels change from single-row execution, and are they correct against supplied labels? We define the quantities for these questions before describing how the checker selects a size.

Let $T=(r_1,\ldots,r_N)$ be the input to the semantic filter: $N$ is the number of rows after any structured filtering. Each row occurrence has a distinct ID. A complete plan returns $b_i\in\{0,1\}$ for every row $i$, where one means yes. The database, rather than the model, adds those labels to obtain its count $C_b$. Supplied dataset labels $g_i\in\{0,1\}$ give a separate source count $G$:
\begin{equation}
C_b=\sum_{i=1}^{N}b_i,\qquad G=\sum_{i=1}^{N}g_i.
\label{eq:counts}
\end{equation}
For the running Sports execution, $N=2,048$, $C_b=519$ and $G=517$. Source accuracy asks how the plan compares with these supplied labels.

Reference fidelity asks another question: how much did the plan change the labels produced by single-row execution? We call one-row-per-prompt execution \emph{singleton execution}. S1 and S2 are two complete singleton runs with fresh model responses. Their labels $s_i^{(1)}$ and $s_i^{(2)}$ are evaluation references. Both return 530 in the Sports case. The checker obtains its own sampled singleton responses. S1, S2 and the supplied source labels are used only for evaluation; they never enter size selection.

\subsection{How Many Labels Changed?}
The reference loss is the fraction of rows whose plan label differs from a reference:
\begin{equation}
d_j(b)=\frac{1}{N}\sum_{i=1}^{N}\ind[b_i\ne s_i^{(j)}],\qquad j=1,2.
\label{eq:fidelity}
\end{equation}
The bracket contributes one for a disagreement and zero otherwise. In Sports, $d_1=d_2=17/2,048\approx.83\%$. We report $d_{\max}=\max(d_1,d_2)$ so that meeting a 5\% threshold means meeting it against both observed references. These references are model outputs; matching them does not establish agreement with source labels.

\subsection{How Far Is the Returned Count from the Source?}
Row errors and COUNT errors answer different application needs. We report
\begin{equation}
\begin{aligned}
e_{\rm row}&=\frac{\sum_{i=1}^{N}\ind[b_i\ne g_i]}{N},\\
e_N&=\frac{|C_b-G|}{N},\qquad e_G=\frac{|C_b-G|}{G}\quad(G>0).
\end{aligned}
\label{eq:task}
\end{equation}
Here $e_{\rm row}$ is the fraction of incorrect row labels. The COUNT errors share a numerator: $e_N$ divides by all $N$ input rows, whereas $e_G$ divides by the $G$ source-positive rows. We report $G=0$ separately; $e_G$ can exceed 100\% when the absolute error is larger than $G$.

In Sports, 18 rows are counted despite negative source labels (false positives), while 16 source-positive rows are missed (false negatives). There are $18+16=34$ wrong labels, but COUNT is high by only $18-16=2$. Thus $e_{\rm row}=1.66\%$, $e_N=.10\%$ and $e_G=.39\%$. Wrong labels can cancel in a count; they remain wrong if another query reuses those labels. Writing $C_{S_j}=\sum_i s_i^{(j)}$ for reference $j$'s count, changing $d_jN$ labels can change that count by at most $d_jN$: each changed label adds or removes one. Hence $|C_b-C_{S_j}|/N\le d_j$. This bounds disagreement with the reference count, rather than error against source $G$. All COUNT controls below use the additive tolerance $.05N$.

\subsection{Did the Engine Return a Complete Result?}
We keep output delivery separate from both accuracy measures. \emph{Native delivery} means that the engine returns a Boolean for every row and hence a COUNT. LOTUS's native parser looks for \texttt{true} before \texttt{false} after the first \texttt{Answer:}, or in the whole response if that prefix is absent. It defaults to \texttt{True} when neither occurs. An additional \emph{strict-format check} accepts only a standalone Boolean, optionally prefixed by \texttt{Answer:}. For example, observed Qwen responses \texttt{Answer: Sports} and \texttt{Answer: Sci/Tech} trigger a native default but fail the strict check. A native count can therefore exist when a strict-format count is unavailable.

The custom batch operator requests a JSON object containing all $k$ local row IDs and Boolean labels. Every required label must be valid; one missing or invalid label makes that batch incomplete. A complete label vector contains one label for every input row. Strict-reference fidelity requires such a vector from both the plan and each reference, with every response passing the format check. Keeping only valid rows would change the query's input and count.

Finally, a \emph{probe} is a test used to choose a size. Its artificial batch may overlap other probes, and only one designated label is scored. Deployment instead partitions $T$ and labels every occurrence exactly once. A probability bound for a sampled probe and a measured loss for a complete deployed result are therefore reported separately. Section~\ref{sec:budget} makes this distinction operational.
