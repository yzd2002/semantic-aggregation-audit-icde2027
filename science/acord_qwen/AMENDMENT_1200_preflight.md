# ACORD input-length amendment, before model inference

The initial pre-inference protocol specified 600 Unicode code points per clause. After sampling ACORD inputs and seeing that 1,086/1,824 uniform and 1,196/1,824 case-control candidate occurrences exceeded that length, but before any ACORD model inference, we evaluate a fixed 1,200-code-point prefix for the same candidate IDs, order, query text, reference labels and two scenarios. This is an amendment after inspecting sample composition, not a protocol fixed before sampling or external preregistration. It changes the input, not the target label or selected pool.

Decision rule fixed before the 1,200-character tokenizer preflight: if every original, stable-ID reverse and pointwise prompt including a retry suffix and its output-token cap fits within the 4,096-token context, the 1,200-character version becomes the planned primary ACORD inference input. Otherwise retain the original 600-character version as primary, record all overflow counts, and do not silently delete or truncate selected candidates further. This choice is based solely on context fit and seeks to expose more source text; it does not guarantee that the resulting prefix contains all information used by the annotators, and it is not based on model outputs.

The primary remains the case-control Qwen selective-minus-keyed query-macro MAE on common-complete pools, with the original target Y=source score 3 or 4. The 1,200- and 600-character inputs are not independent samples; if both are later run, model execution order, runtime and label reuse must be disclosed and no causal conclusion assumed. No new LLM outcomes, legal advice or deployment results are claimed by this preparation.
