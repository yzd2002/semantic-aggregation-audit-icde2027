# ACORD legal-clause transfer: frozen pre-inference design

Status: prepared after examining the earlier ESCI, WANDS, TREC-COVID and three-model results, but before ACORD dataset download, sampling or model inference. This is not external registration, a blind model pretraining guarantee, a fresh-machine replication, or evidence of legal utility. Exact deviations must be recorded rather than silently changing this plan.

Source: The Atticus Project ACORD revision 942b33a7c6fed7ead362c7c296401086f8bc0321, data archive Git blob 6de8c6c01a5221fe7669bc3117cfc02e5bc02fbc. The accompanying ACL 2025 paper and source README document explicit relevance scores 0--4 corresponding to lawyer ratings 1--5 stars; score 0 also includes additional negatives inferred from clause source/category, so not every zero is asserted to be individually lawyer-annotated. Missing query--clause pairs are unknown and must never be relabeled negative. The README says dataset CC BY 4.0 while the repository LICENSE is MIT; retain both and check rights of underlying contract text before distribution.

Task: fixed-pool clause relevance proxy. Define Y as score 3 or 4 (4/5 stars: meets most or all query aspects); define N as score 0, 1 or 2. This task threshold is selected from the published rubric, not validation against actual drafting quality. Query and candidate texts shown to the model are a fixed prefix, with 600 Unicode code points of clause text; record truncation. The source query is the task specification. Adapt the biomedical-style semantic predicate to ask whether the clause addresses most of the drafting query's stated substantive requirements, allowing minor omissions. No legal advice, deployment safety, or true user satisfaction is inferred.

Population: all test-split queries with nonempty query text and at least 32 distinct explicitly scored candidate clauses with nonempty text. Conflicting duplicate query--clause scores invalidate the affected pair; identical duplicate rows are collapsed. Never use unjudged rows. Missing referenced corpus records are reported, not silently treated as negatives. All query and clause IDs are sorted as strings before any randomization. Log source hashes, eligible query count, excluded entries, duplicate counts and query IDs.

Two pool constructions, 32 distinct candidates per eligible query:
1. Uniform-judged: uniformly sample 32 without replacement among explicitly scored candidate clauses, regardless of label. This includes the source's expanded zero-score rows and does not represent a live retrieval distribution.
2. Case-control stress pool (primary): sample without replacement up to eight score>=3, eight scores 1--2, and sixteen score=0; fill any shortfall uniformly from remaining explicitly scored candidates. This intentionally uses reference labels during sampling, so its positive fraction is engineered and not population prevalence. The two pools may overlap; they are paired scenarios, not independent samples.

For each query and scenario, derive a reproducible pseudorandom seed from SHA-256 of UTF-8 `ACORD-20261101\0<scenario>\0<query-id>`. Select from sorted IDs using Python random.Random, then independently shuffle the 32 selected occurrences with the same generator. Record raw selected IDs and full labels only in private results; model prompts must not include labels. Do not inspect model predictions before the policy and inputs are frozen.

Plans on Qwen3-4B-Instruct-2507, previously hashed local weights: one source-query-based fixed specification; four eight-item ID-keyed batches in original order; identical replay; stable-ID within-chunk reversal; a selective pointwise call only for valid keyed disagreements; and full pointwise diagnostics. Use the same structural contract, guided Y/N JSON grammar, deterministic temperature, retries, 128-token keyed/4-token pointwise output caps, and 4096-token context as TREC-COVID. If a prompt plus output cap exceeds 4096, declare the pool non-estimable and preserve the failure, without altering the pool or unilaterally dropping labels. Run only when resources and GPU ownership permit; preserve initial responses, retry records, token counts, costs and inference environment. Single-GPU offline timing is not production latency. A second model, if run, is a separate sensitivity follow-up rather than a substitute for the primary model.

Primary analysis: on the case-control sample, Qwen selective-fallback minus canonical keyed query-macro ratio MAE on their common-complete pools. Report completion over all attempted pools; a 95% percentile query bootstrap over 4,000 paired resamples is descriptive, not a population guarantee. Record all failures and include both scores. Within each sampled query, also compute midpoint-of-two-keyed-ratios and the all-query-words lexical tie-breaker as pre-inference fixed comparators; the midpoint has no candidate-level F1. Report pooled F1, balanced accuracy and ratio MAE for valid binary plans, logical model call and input-token counts, plus unadjusted paired contrasts against both references. A product/contract reweighting sensitivity changes the pool target and is not a fixed-pool confidence interval. Uniform-judged results, zero-score composition, size/truncation and any model sensitivity are secondary; no claim of overall population prevalence or superiority.

Retain query labels only for scoring, not for prompt or model routing. The case-control pool uses labels solely to construct an intentionally controlled benchmark. Data selection and results may depend on shared clauses and public benchmark exposure; query bootstrap does not repair that. Any independent release must pass the author's license, privacy, identity and source-data rights review.
