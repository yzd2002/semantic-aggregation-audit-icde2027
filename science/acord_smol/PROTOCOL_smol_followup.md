# ACORD SmolLM2 sensitivity follow-up, fixed before this model's inference

This follow-up is designed after the Qwen ACORD results, prior datasets and labels have been inspected. It is neither an independent sample nor external preregistration and must not be used as a confirmatory blind test. SmolLM2's pretraining exposure to ACORD is unknown. Preserve all failures and do not change this design after examining SmolLM2 outputs.

Use exactly the existing 114 ACORD pools, candidate order, source query specification, original 2,400-Unicode-code-point clause prefixes, reference-score mapping, system and user prompts, stable local IDs, constrained output grammars, deterministic decoding, retry policy and analysis definitions of the Qwen run. The two scenarios share 57 queries and some clauses; the case-control scenario uses labels in sampling, and the uniform-judged scenario has few positives. Some source zero grades are category-expanded and some clause text remains truncated; these pools are not a live retrieval distribution and relevance labels are not legal advice or satisfaction.

Use local HuggingFaceTB/SmolLM2-1.7B-Instruct at revision 31b70e2e869a7173562077fd711b654946d38674, whose weight SHA-256 is f55217be716b6a997b97b9d8d7eb6fad02e00858f5010ec24f64603c3a98a0e8. Verify weight and tokenizer assets, the recorded vLLM V1 dependency versions and the actual model chat template. Before model inference, tokenize all 4,560 distinct keyed-original, stable-reverse and pointwise prompts including the retry suffix and response-token cap. Use 4,096 context if all fit; otherwise use 8,192 only if all fit and model config supports it. If any prompt exceeds 8,192, do not run this comparison; do not drop candidates, shorten texts or change labels after seeing outputs. Keep all preflight results.

Run ordinary, guided-keyed and guided-pointwise negative controls before any candidate judgment; stop if any fails. Then run original keyed, stable-ID reversed keyed, selective pointwise only for valid disagreements, identical original replay and full pointwise, in that order. Report completion, retries, all raw responses, output token counts and calls, and single-GPU offline time. The fixed samples, prompt content and references match Qwen; models, tokenizers and chat templates differ, so outputs, token counts and runtime are not causal effects of model size and cannot be used as production latency.

On each scenario's common-complete pools report query-macro ratio MAE, pooled F1 and balanced accuracy for keyed and selective, full pointwise, all-N, lexical tie-breaker and the no-label midpoint of keyed ratios. The primary within-Smol contrast is case-control selective minus original MAE with a descriptive unadjusted 95% query-bootstrap interval using 4,000 resamples; the uniform scenario and other contrasts are secondary. Report counts for all attempted pools and failures. Use the same analysis as Qwen where possible and preserve the separate full-pointwise supplement correction and its provenance.

As an exploratory matched-query analysis, on case-control queries complete for both models compute the mean per-query difference in within-model effects (Smol selective-minus-original MAE minus Qwen selective-minus-original MAE), with 4,000 paired query-bootstrap draws seeded 20261111. Also report each model's two MAEs, completion counts and the shared denominator. This difference is descriptive on the reused public benchmark, not an architecture effect or a new independent study. If either model lacks complete queries, report the attempted-to-complete attrition and evaluate quality only on the shared intersection. No filtering, hyperparameter tuning or alternate baseline selection after observing Smol outputs.
