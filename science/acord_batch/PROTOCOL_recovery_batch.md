# ACORD four/eight fixed-pool comparison after environment restart

This is a local post-hoc, reused-sample sensitivity check, not a preregistered or independent evaluation. Both ACORD scenarios, their labels, earlier model results, and the aggregate of an earlier four-item run were already observed. That earlier run lost its per-response files when the temporary filesystem was cleared; `RECOVERY_HISTORY.md` records its visible summary and must not be used as a substitute for the missing traces. Record every outcome of the recovery run, whether favorable or not; do not select the execution or prompt based on results.

The original vLLM run used xgrammar 0.1.23, outlines-core 0.2.11 and setuptools 79.0.1. They cannot currently be restored from the available package sources. The remaining machine environment has xgrammar 0.1.25, outlines-core 0.1.26 and setuptools 80.9.0, which conflict with vLLM 0.10.2's pinned requirements. This is an unsupported configuration, not a clean replication. To compare chunk plans under the same new software, rerun **both** eight-item and four-item keyed originals in the same process, same Qwen weights, 114 previously fixed pools, 2,400-character prefixes, system and user instructions, vLLM V1 settings, temperature zero, 128 output-token cap and retry policy. Use sizes eight and four with consecutive partitions, IDs 1--8 or 1--4 and strict ascending-key Y/N JSON. Partitions, IDs, grammar lengths and execution scheduling change along with chunk size; no resulting difference is a causal batch-size effect. Test the xgrammar guided-output control against the same contradictory BANANA instruction for both sizes before starting any candidate judgments; a failed control stops the experiment.

Run in fixed order: eight-original, four-original, four-stable-ID-reverse, four-identical-prompt-replay, eight-identical-prompt-replay. Each chunk can retry at most once after strict format failure. An aggregate is reported only if all 32 candidates resolve. Save untrimmed first/final responses, input/output token counts, prompt hashes, finish reasons, actual attempts, code and configuration, immediately on persistent storage after each mode. The same machine and GPU are used; timings are offline batch generation, not production latency.

Before any model inference, use the same Qwen tokenizer to check every original and stable-ID-reversed prompt at both sizes, including the retry suffix and 128-token budget; stop if any exceed the 4,096-token context. Check hashes of the fixed 114-pool selection, prior baseline, model weight files, tokenizer files, code, protocol and environment. Do not change another user's process or erase data; stop this run if GPU ownership or resource guards fail.

The primary descriptive contrast is four-minus-eight query-macro ratio MAE on the 57 label-constructed stress pools jointly complete for both new original plans. Report an unadjusted paired 95% query-bootstrap interval with 4,000 resamples and seed 20261113. Report uniform-pool results with seed 20261114, pool completion, pooled F1 and balanced accuracy, all-negative reference, saved prior pointwise reference, reverse/replay label changes and actual counts/tokens. When using the saved pointwise reference, disclose that it comes from the earlier execution and prior software. Record the prior and current eight-item original-label disagreement as an environment/execution sensitivity, not a causal software ablation. The scenarios share 57 queries and have labels used in pool construction; many clauses are truncated, some negatives are source-expanded, legal correctness is not evaluated, and model pretraining exposure is unknown.
