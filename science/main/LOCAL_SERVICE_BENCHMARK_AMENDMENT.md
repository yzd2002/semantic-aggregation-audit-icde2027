# Local-service benchmark continuation amendment

Before continuation, the original fixed-order run completed the first condition, pointwise at four active queries, including all 52 attempted pools. Three pointwise requests experienced `ReadError` on the loopback connection. The affected three pools abstained; the original runner wrote their records and then stopped as written. The server log showed no corresponding HTTP error status; the underlying transport cause remains unestablished. The complete original first-condition records, summary, control, and runner traceback are retained in `run_local_service_initial_aborted/`. No request or pool from that condition was repeated or replaced.

The protocol had specified that HTTP failures are not retried or imputed and that failed outcomes are reported. To permit all preselected conditions to be observed, this amendment continues the remaining eleven conditions in the originally fixed order. It keeps the original first condition and preserves the original client request logic, models, prompts, query order, server, decoding, fan-out, timeout, failure handling, and per-condition measurements. A new client connection pool is opened at continuation; there is a pause between the first and second conditions. The server remained loaded throughout. The pause is excluded from each condition's measured wall time. Conditions continue after individual request failures; if all 52 pools in a condition fail, the continuation stops after recording that condition so an unavailable service cannot silently consume the rest of the schedule.

The first condition is already observed, so this amendment is not a fully prospectively frozen study. It changes no saved measurements. All failed and completed pools will be reported, and latency percentiles apply only to complete pools. The continuation program and hashes of this amendment, original observed files, and the unchanged earlier frozen program and protocol are saved before measuring the remaining conditions. This local transport incident limits comparisons and is not evidence of production reliability.
