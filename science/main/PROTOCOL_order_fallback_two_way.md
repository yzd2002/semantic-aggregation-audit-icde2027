# Secondary crossed query–product resampling for the fallback contrast

After selecting the new sample and starting inference, but before inspecting any candidate-level model outputs, we observed that the 3,072 query–product judgments contain 2,987 unique sampled product IDs, 83 of which recur across queries. We therefore fix this **secondary descriptive sensitivity analysis** in addition to—not instead of—the pre-specified primary query-cluster bootstrap. The product multiplicities alter the within-query weighted candidate distribution; this procedure is not an exact coverage guarantee for the primary fixed-pool estimand.

On the original keyed, replay, reversed keyed and full pointwise common-complete queries, independently sample the observed number of query IDs and the observed number of distinct product IDs with replacement. Each query receives its sampled multiplicity; each judgment receives the multiplicity of its product ID. Within each query, use the product multiplicities to compute a weighted predicted-positive ratio for the canonical keyed and pointwise-fallback plans, and a weighted reference-positive ratio. Compute each plan's absolute ratio error, then take the query-multiplicity-weighted average of fallback minus canonical. Fail if any resampled query with positive query multiplicity has zero total product weight; do not silently discard draws. Use 4,000 draws and NumPy `default_rng(20271128)`; within each draw sample all query indices first and then product indices. Sort distinct product IDs numerically for indexing; use saved common-query order. Report the 2.5th and 97.5th percentiles alongside the unaltered primary interval.

This is a pigeonhole-style sensitivity inspired by Owen, *The Pigeonhole Bootstrap*, Annals of Applied Statistics 1(2), 386–411, 2007, https://arxiv.org/abs/0712.1111 . Products were sampled conditional on queries, some recur across queries, the quantity is nonlinear, and weighted candidate pools differ from the original fixed pools. Neither this interval nor the primary interval fixes source selection, unjudged candidates, public model pretraining exposure, specification errors or missing user outcomes. Preserve this secondary result regardless of its direction.
