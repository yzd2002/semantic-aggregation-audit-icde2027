# Secondary query–product bootstrap sensitivity (fixed before inspecting model outcomes)

The frozen holdout contains 5,120 query–product judgments but only 4,836 distinct sampled product IDs, so some products recur across queries. The primary query-cluster bootstrap in `PROTOCOL_wands_holdout.md` does not explicitly resample products. After the holdout was selected and inference had started, but before inspecting any holdout model outputs, add the following **secondary descriptive sensitivity analysis**. It does not replace the pre-specified primary criterion or establish independent product sampling.

On the same three-condition common-complete pools for each model, compare replay versus stable-ID reversal. Let each retained judgment have query index $i$, product index $j$, and disagreement indicator $z_{ij}$. For each of 4,000 resamples, independently draw the observed number of common query IDs with replacement and the observed number of distinct product IDs with replacement. Give judgment $(i,j)$ weight equal to its query multiplicity times its product multiplicity. Compute the weighted fraction of disagreements; if all weights are zero, fail rather than silently discard the replicate. Use NumPy `default_rng(20271124)` and, for each resample, draw all query indices first and then all product indices. Report the 2.5th and 97.5th percentiles alongside the unchanged primary query-only bootstrap interval. Product IDs are ordered numerically for indexing; queries use the saved common-pool order.

This is a pigeonhole-style crossed query–product resampling sensitivity inspired by Art B. Owen, *The Pigeonhole Bootstrap*, Annals of Applied Statistics 1(2), 386–411, 2007, doi:10.1214/07-AOAS122 (https://arxiv.org/abs/0712.1111). It resamples factors from the observed sparse workload; the selected products were not sampled independently of queries, and the ratio is nonlinear. Neither interval corrects missing judgments, pool selection, public-model training exposure or all dependence, so neither is claimed as exact population coverage. Preserve the output, code and fixed seeds, and report this analysis as secondary regardless of its result.
