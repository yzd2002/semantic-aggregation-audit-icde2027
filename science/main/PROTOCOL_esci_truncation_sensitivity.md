# ESCI product-text truncation sensitivity

This follow-up is designed after the original ESCI, WANDS, TREC-COVID and failure-fallback results were observed, but before reconstructing the longer texts or generating these outputs. It reuses the existing 250 original ESCI query pools and their 5,160 judged candidates; it is not a new dataset, a blinded validation or a test of actual purchasing satisfaction. Its purpose is to check whether extending the model-visible prefix of the same source product text changes predictions or ratio error. Public pretraining exposure is unknown, and labels may reflect information outside either visible prefix.

## Fixed inputs

Use the original Amazon Shopping Queries products Parquet at the SHA-256 recorded in `OFFICIAL_DATA_SHA256.txt`, filter to US locale and the product IDs already present in `run_full_pools_250/inputs.jsonl`, and reject duplicate product keys or missing joins. Rebuild each product text in the original field order: title, description, bullet points, brand, color; include nonempty string fields and join them with one space, exactly as `run_full_pools.py`. Require its first 600 characters to equal the archived text, and construct a longer alternative as the first 1,200 characters of the same joined string. Keep all 250 queries and all candidates, original order, IDs and reference labels; do not select cases by grade or outcome. Record source and selected-input hashes, counts of texts longer than 600 and 1,200 characters, and the exact selected inputs. A longer prefix can still omit information, change the apparent evidence or expose misleading text; it is not automatically a better semantic reference.

## Fixed execution

Use Qwen3-4B-Instruct-2507 with the recorded model/tokenizer hashes, vLLM 0.10.2 V1 and the same process-local declared-dependency overlay described in `PROTOCOL_vllm_declared_deps_smoke.md`. The inherited environment has other unresolved package conflicts and is not a clean installation. Use one RTX 5090, bfloat16, temperature zero, 4,096-token context, eager mode, prefix caching and at most 16 concurrent sequences. Require no other GPU process before loading; check ownership after loading and before each generation, and stop our run if another process appears. Do not stop other processes.

Use the original `run_experiment.SYSTEM` and `p_point` text, except for the specified 600- or 1,200-character product prefix. Apply the same `[YN]` grammar, four-token cap and one bounded format retry to every request. Before candidate inference, require that an unconstrained incompatible BANANA instruction fails the strict one-label parser and the corresponding guided output passes it. Check all possible original, longer and retry prompts against the context limit before loading the GPU model. Preserve prompt hashes, exact first and final raw responses, finish reasons, retries, model/token counts, execution order and context bounds.

Run three full candidate passes in this fixed order: 600-character prefix, 1,200-character prefix, and an identical-prompt replay of the 600-character prefix. Both variants use the same original query and candidate IDs. Do not replace a failed output with a label; a pool with any unresolved judgment is incomplete for that pass. Fixed sequence, caching and model execution may influence outputs; one replay cannot isolate a pure causal effect of extra text.

## Fixed analysis

On pools jointly complete in all three passes, report pooled candidate F1 and balanced accuracy and query-macro ratio MAE for each pass. The primary descriptive contrast is **longer minus shorter ratio MAE**, with 4,000 paired query-cluster bootstrap draws from NumPy `default_rng(20271101)` and 2.5th/97.5th percentiles. Report the sign and interval regardless of outcome; this comparison was motivated by previously observed results and is not multiplicity-adjusted or a population guarantee.

Report candidate-label change rates for longer versus shorter and replay versus shorter, overall and separately for candidates whose visible text actually changed. Also report the number of changed and unchanged inputs, pool completion, calls and logical token counts; unchanged-text comparisons describe execution variation, not truncation. Use candidate-weighted rates and save all per-query decisions. Differences between long and short may reflect additional irrelevant text, output instability, fixed execution order and interactions with the prompt. Neither more characters nor a valid grammar proves correctness.

As a secondary, deliberately nonstandard product-dependence sensitivity, sort distinct product IDs in common-complete pools and, for each of 4,000 draws from NumPy `default_rng(20271102)`, first resample the number of query IDs with replacement, then draw one independent `Exp(1)` weight per distinct product ID. Apply the same product weight to every occurrence of that ID; within each query use weighted gold and predicted positive fractions, then average the longer-minus-shorter absolute ratio-error difference over sampled queries. The positive weights avoid zero-weight queries. Report the 2.5th/97.5th percentiles as a **reweighted-pool sensitivity range**, not a frequentist confidence interval or exact coverage for the original fixed-pool estimand. Shared products, selected judged candidates, truncated text and public-data exposure remain limitations.

Freeze the protocol, selector, runner, analysis, independent verifiers, synthetic edge checks, old inputs, model/source manifests and context preflight before inference. Preserve failed setup or execution attempts and never replace prior outputs.
