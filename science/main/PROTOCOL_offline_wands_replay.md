# Same-machine isolated-environment replay of previously observed WANDS inputs

This is a post-hoc reproducibility diagnostic, not a blinded evaluation, independent dataset, or semantic quality comparison. It is specified after the offline isolated environment's synthetic format controls succeeded but before running these WANDS prompts in that environment. Select the first 16 rows in the saved `wands_holdout_selection/inputs.jsonl` order, without filtering by outcomes or label grades; each row has 32 candidates. Reuse each row's saved Qwen specification or fallback from `run_wands_holdout_qwen_v1/specifications.jsonl`. Model-visible prompts contain query, specification where valid, and candidate ID/text only; gold labels are not sent to the model.

For each of the 16 queries, split the original candidate order into the same four consecutive eight-product chunks and preserve original local IDs. Run the saved original, identical-prompt replay, and stable-ID reversal conditions, in that fixed order. Each condition has 64 model calls before any retry. Use the same Qwen3-4B-Instruct-2507 model, V1, 4,096-token context, bfloat16, eager execution, 0.70 memory fraction, prefix caching, at most 16 concurrent sequences, temperature zero, exact-length `[YN]{8}` output and 32-token cap as the holdout protocol. Require an incompatible unconstrained negative control to fail strict parsing and the guided control to pass before running product prompts. Preflight each prompt and possible retry against the context limit. Check for foreign GPU processes before model loading, after initialization and before every generation call; stop only this run if one appears.

Use the saved original, replay and reverse output records as fixed comparators. Reconstruct each prompt and require its hash, query ID, chunk start, size and mapping to agree with the corresponding recorded input before inference. Permit one format retry using the original retry suffix. Preserve first and final raw outputs, finish reasons, logical token counts, prompt hashes, candidate mappings, retries, parse validity and complete-pool status; do not replace missing judgments by a label. Compare current and earlier parsed labels only for jointly valid chunks and report all attempted and incomplete chunks and pools. For each condition report changed candidate count, comparable candidate count, identical raw-final-output chunks, and changed queries. Also report original-versus-replay changes in the new run. Save all outcomes regardless of direction; no statistical significance or population inference is intended.

The saved specifications, sample and outputs were previously observed, and the 16-row prefix is not a random independent sample. This replay uses the same GPU and model but a local-copy isolated environment and fewer prompts per generation batch than the earlier 160-query run. Environment files, scheduling, execution order and other runtime factors may differ; matching outputs are not a proof of cross-machine reproduction, and mismatches cannot be attributed to one cause. Timing is not compared. Independently reconstruct prompts, output mappings, retries and all reported counts from the saved records, optionally verifying token lengths with the local tokenizer.

Freeze this protocol, the runner and independent verifier, selection, saved specifications and all three previous output files, shared prompt/parser code and model manifests before inference. Preserve the synthetic checks, failed environment setup attempts and any failed replay output; never overwrite an earlier result.
