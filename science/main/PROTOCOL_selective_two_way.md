# Secondary crossed resampling for actual selective execution

After selection and the start of inference, but before inspecting model outputs, the 1,664 judged query–product pairs contain 1,622 unique sampled product IDs, of which 41 occur in multiple queries. We therefore fix this secondary query–product resampling sensitivity, in addition to the unchanged primary query-cluster analysis. Product resampling changes within-query candidate weights; it is not an exact interval for the original fixed pools.

On the common-complete queries defined in `PROTOCOL_selective_execution.md`, independently resample the observed number of query IDs and the observed number of distinct product IDs with replacement. Each judgment receives the sampled multiplicity of its product; each query receives its sampled query multiplicity. For each selected query compute the product-weighted reference-positive, canonical-keyed-positive, and actual-selective-fallback-positive ratios, then the difference of absolute errors. Take the query-multiplicity-weighted mean of that difference. If any resampled query with positive query multiplicity has zero total product weight, fail rather than discard the draw. Use 4,000 draws, NumPy `default_rng(20271201)`, sampling query indices before product indices each draw. Sort product IDs numerically and retain common queries in saved order. Report the 2.5th and 97.5th percentiles, regardless of direction.

This pigeonhole-style sensitivity is inspired by Owen, *The Pigeonhole Bootstrap*, Annals of Applied Statistics 1(2), 386–411, 2007, https://arxiv.org/abs/0712.1111 . Product inclusion depends on query and previous-sample exclusions; ratios and absolute errors are nonlinear. Neither this interval nor the primary query bootstrap corrects selection, public-model exposure, missing product information, unjudged candidates or the use of relevance labels instead of purchase outcomes.
