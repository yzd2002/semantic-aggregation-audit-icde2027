# Actual selective execution on the remaining eligible WANDS queries

This follow-up is designed **after** the prior 96-query, trace-derived fallback result was observed, but before selecting products or running these new model outputs. Its purpose is to execute an actual selective scheduler and repeat the same pre-specified ratio-MAE comparison on different queries and sampled products. It is not a new dataset, a blinded external replication, an online-service benchmark or evidence about purchase satisfaction. Model pretraining exposure to public WANDS is unknown.

## Fixed sample

Verify the same pinned WANDS source hashes, unique keys, foreign keys and grades. Collapse identical duplicate query–product grades to the smallest annotation ID and exclude conflicting-grade pairs. Exclude all normalized (trimmed, case-folded) query strings in the earlier three ESCI samples and all three WANDS samples; exclude every product ID actually sampled in those WANDS samples. Using only counts, before writing this protocol we found 52 remaining eligible WANDS queries with at least 32 nonconflicting judgments after these exclusions. Include **all 52 eligible queries**, sorted by query ID, and fail if that count differs. For each query sort remaining candidates by annotation ID and product ID; sample 32 without replacement and then shuffle using a query-specific `random.Random` seeded by the first eight bytes of SHA-256 of `20271129`, a NUL and the decimal query ID. Do not stratify grades or replace cases after seeing outcomes. Preserve and independently verify source IDs, texts, labels and order. Products may recur across the new queries; exclusion is from prior sampled products only.

## Fixed execution

Use the prior Qwen3-4B-Instruct-2507 model and recorded hashes, WANDS exact-only task instruction, query specification, product text, vLLM 0.10.2 V1, bfloat16, temperature zero, one RTX 5090, eager mode, 4,096-token context, prefix caching and 16 concurrent sequences. Verify both the keyed JSON and single-label regex constraints against incompatible BANANA instructions before candidate evaluation; fail closed if either control fails. Generate each query specification with one retry and the existing direct fallback, preserving responses. On consecutive eight-item chunks with stable local IDs, execute keyed original and stable-ID reversal, with fixed-key Y/N JSON, a 128-token cap and one retry. Parse labels by ID.

**Actually construct and send a pointwise model request only for a product whose two valid keyed responses disagree.** Use the same query, specification when valid, and product text with a `[YN]` regex, four-token cap and one retry. Preserve raw responses, their product association, prompt hashes, retry outcomes and token counts. If an underlying keyed chunk is invalid or a required selective response remains invalid, the pool is non-estimable; do not impute a decision. Combine cached keyed outputs symmetrically: retain an agreeing label and otherwise use the actual selective pointwise response. Sort the same chunk by stable IDs for the canonical-keyed comparator. Fixed IDs, unchanged chunk membership and cached responses are necessary to interpret this limited symmetry; repeated model calls need not be deterministic.

After the selective stage, run an identical-prompt replay of keyed original and a **full pointwise comparator on all candidates** in that fixed order. Compare actual selective pointwise responses with the later full-pointwise responses for the same product and prompt, retaining differences. The full-pointwise comparator is diagnostic and does not supply the actual selective plan's values. Save initial and retry responses, finish reasons, prompt hashes, logical input/output token counts, failed calls and worst prompt-plus-output bounds. Capture the actual end-to-end *offline batch* wall time from specification preparation through construction and execution of the selective plan, excluding model loading, the negative controls and the later replay/full baselines. This is one fixed-order batch on one GPU with warm prefix caching; it is not a per-user or production latency measurement and should not be compared as a general speedup.

## Fixed analysis

The primary comparison is query-macro ratio MAE, **actual selective fallback minus canonical keyed original**, on pools jointly completed by original, reverse, keyed replay and full pointwise plans and with every needed selective response complete. Use 4,000 paired query-cluster bootstrap draws with NumPy `default_rng(20271130)`; report the 2.5th and 97.5th percentiles, the sign of the point difference and whether the upper endpoint is below zero, regardless of direction. This is a repeated benchmark-specific criterion chosen after observing the previous sample's result, not an independent population or user-satisfaction guarantee. All 52 eligible remaining query IDs are included, and candidate selection, task labels and model inputs remain conditional on the public WANDS source.

Also report full completion, pooled candidate F1 and balanced accuracy, query-macro ratio MAE, keyed replay differences, actual selective-versus-later-full pointwise differences on matched disagreements, and a diagnostic trace-derived variant that substitutes the later full-pointwise labels for the actual selective ones. Include the deterministic all-query-words and all-negative comparators. Report actual selective-stage calls, total calls including specification and both keyed passes, logical token counts, failure counts and the captured batch duration. Replays and full-pointwise calls are separate diagnostic costs, not part of the selective plan's cost. Intervals for secondary comparisons are descriptive and not multiplicity-adjusted. Preserve every outcome, including failure, null or worse effects. The sample may repeat products across queries and uses relevance labels and truncated text; query bootstrap does not fix these or source-selection bias.
