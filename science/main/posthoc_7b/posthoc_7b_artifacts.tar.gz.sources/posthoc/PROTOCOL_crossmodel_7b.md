# Additional planned paired model comparison

Before seeing any Qwen2.5-7B candidate outputs, in addition to the existing within-model selective-minus-keyed contrast, compare Qwen2.5-7B-Instruct and the already observed Qwen3-4B-Instruct-2507 on the same 250 ESCI pools. The data, 4B outcomes and labels were already exposed, so this is a post-hoc sensitivity analysis. The models differ in family version, size, prompts after specification, model tokenizer, chat template and other factors. It cannot establish an effect of parameter count, a general model ranking, independence from training data, actual satisfaction, or out-of-domain performance.

Use the intersection of pools complete for all five model plans (original keyed, stable-ID reversal, replay, actual selective fallback and full pointwise) in both runs. Do not replace failures or change this set by method. For original keyed, actual selective, and full pointwise separately, report each model's query-macro ratio MAE and the 7B-minus-4B difference with a 4,000-resample paired query-bootstrap percentile interval using NumPy default_rng seed 20271031 and a shared resampling index across the three contrasts. Report the number and IDs of included pools, completion counts and the all-Y MAE on the same subset. As a secondary descriptive diagnostic, also report each model’s query-macro signed error (predicted ratio minus reference ratio) for the same three plans; this is not a calibration guarantee. If there are no common pools, report the empty comparison and failure counts rather than fabricating numbers. These are descriptive comparisons without multiple-testing correction; shared products and source selection can violate simple independence interpretations.

Rebuild the predictions from the recorded keyed and actual selective responses using the existing analyzer; validate the new 7B run separately with the independent prompt/route/tokenizer verifier. Fixed reference labels, full sample and prior Qwen3-4B raw outputs are byte-hashed before new model inference. The bootstrap interval is not a production guarantee, and reduced logical request count does not prove lower cost or latency.
