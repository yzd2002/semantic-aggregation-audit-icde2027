# Post-hoc schema-guided specification sensitivity

This experiment is designed after seeing the full Qwen2.5-7B results and diagnosing the specification failures. It reuses the already observed 250 ESCI queries and 52 WANDS queries and is not a blinded confirmation, a new sample, or a model-size experiment. In the original 7B run, every product specification failed strict validation and both plans fell back to direct keyed judgment; every final response was a Markdown-fenced block. Removing fences retrospectively yields valid strict objects for 242/250 ESCI and 52/52 WANDS, but no downstream 7B judgments were produced using these extracted specifications. The original results and raw responses remain unchanged.

To test an executable alternative, rerun the exact same 7B model, query pools, prompt text, candidate formats, batch size, temperature, token caps, retry rules, GPU settings and selective scheduler as in the prior 7B product runs, with one change: request JSON-schema-guided decoding for the specification stage. The schema defines exactly the product_type, required and preferred fields, with string type, array-of-string types and no extra properties. The product_type has a nonempty-string schema constraint; the existing strict parser still rejects whitespace-only strings and any malformed output. No label or reference information is included in a prompt. The generated specification can be structurally valid and still semantically wrong.

Before any candidate inference, freeze this protocol, the schema, both modified runners, negative-control verifier, prior 7B responses and selected inputs, and comparison code. For each dataset, repeat the existing incompatible-instruction controls for keyed and pointwise formats, and add an incompatible-instruction control for the specification schema; require the unconstrained answer to fail the strict specification parser and the schema-guided answer to pass it. Abort that run if controls fail and retain the failure. Continue to check GPU ownership before each bounded batch, and do not stop or change any other task. If an actual specification remains invalid after one retry, use the original direct fallback, retaining that event.

For each sample independently, report all specification completions and fallbacks, all model-plan completions, candidate F1 and balanced accuracy, query-macro ratio MAE, baseline all-Y and lexical references, original keyed versus actual selective performance, calls and logical tokens. Reconstruct prompts, parser outcomes, routing, alignment and statistics using the independent verifier and the actual model tokenizer. Report timings only as same-host offline measurements; a public-index dependency download may be concurrent, so no latency comparison or deployment-speed claim is made.

As a pre-specified-for-this-post-hoc-run diagnostic, compare the actual schema-guided selective plan with the previous unguided 7B selective plan on their shared common-complete query pools. Use the same fixed sample and a paired query bootstrap with 4,000 draws and NumPy default_rng seed 20271101; report the new-minus-old MAE difference, percentile interval, numbers of common pools and specification fallbacks. Run the two sample comparisons separately and retain all signs, nulls and failures. This compares whole pipelines: decoding constraints, generated text, downstream prompts, and time all change; it cannot isolate one causal mechanism or establish general superiority. Query/product dependence and repeated use of this public sample limit the unadjusted intervals. Do not present results as real purchase satisfaction or clinical utility.
