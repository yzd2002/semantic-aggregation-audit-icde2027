# Official full-pool evaluation protocol (frozen before model inference)

Motivation: the initial derived-format studies deliberately contain only one E product per row, making the positive fraction and the main metric sensitive to pool construction. This study reconstructs all labeled candidate rows per original query ID from Amazon's Shopping Queries Dataset instead.

Inputs: original `shopping_queries_dataset_examples.parquet` and `shopping_queries_dataset_products.parquet` published at https://github.com/amazon-science/esci-data/tree/main/shopping_queries_dataset. Retain example rows with `split=test`, `small_version=1`, `product_locale=us`, and labels in E/S/C/I. Exclude every exact query string appearing in the prior 160-query and 500-query studies. From the remaining query IDs, choose 250 uniformly without replacement with RNG seed 20271103. For each chosen ID, include every retained labeled example (no one-E subsampling); join the US product table on product_id and locale. Order examples by example_id, shuffle using a query-specific SHA-256-derived seed, and then assign sequential candidate indices. Product text concatenates title, description, bullet points, brand and color in the publisher's conversion order, ignoring missing fields, and is limited to the first 600 characters. Preserve empty text as an explicit empty input, and count missing joins rather than silently dropping labeled examples. If duplicate US product IDs occur, stop rather than multiplying rows. This is still the dataset's labeled result list, not an independently observed live search page, and the data are not independent of earlier derived ESCI studies.

Operational reference: E or S -> Y; C or I -> N. The mapping is a relevance-based proxy for satisfaction, not a new human purchase-satisfaction study. Candidate lists may include multiple E products and can exceed eight items.

Plans, prompts, hardware and decoding match the previous protocols: pointwise (P); direct indexed JSON (J); two-stage indexed JSON (TJ); and two-stage compact with direct fallback (TC). For batch methods, split each full pool in order into consecutive chunks of at most eight candidates. Each chunk is independently validated, can be retried at most once, and is assigned local IDs 1..chunk-size. A pool estimate is emitted only if every chunk is valid and, for TJ, its query-level specification is valid. TC uses the direct compact prompt on all chunks when the specification remains invalid after a retry. The final denominator is the entire original labeled candidate list. A pointwise pool fails if any candidate remains invalid after retry. Cap output at 4/192/160/32 tokens for pointwise/JSON/specification/compact, respectively. Use one Qwen3-4B-Instruct-2507 model, vLLM 0.10.2, bfloat16, zero temperature, max context 4096, 16 concurrently scheduled sequences, prefix caching and one RTX 5090. Offline generation time excludes model load and Python processing.

Before seeing model outputs, specify candidate F1, balanced accuracy, pool-ratio MAE, completion, request counts, prompt/output tokens, and wall time; evaluate quality on the common completed pools and report completion over all 250 attempts. Include deterministic all-Y and all-N predictors as pre-specified baselines. Use 4,000 query-ID cluster bootstrap resamples on the common subset for descriptive intervals. This sampling and timing do not support cross-dataset, cross-model, or online-serving claims.

## Before-output baseline amendment

Before inspecting the full-pool model outputs, include a deterministic lexical baseline: case-fold the query and truncated candidate text, extract Unicode word tokens, and predict Y iff the query has at least one token and every distinct query token appears in the candidate text. This has no learned threshold and is a deliberately simple lexical comparator, not a competitive BM25 or learned retrieval system. Compute it on the same common completed pools and report it alongside the constant predictors.

**Timing clarification:** The recorded interval includes chat-template rendering as well as the batched generation call; it excludes model loading and most other Python-side prompt assembly and parsing.
