# Post-hoc stable-ID reversal and identical-prompt replay

This study was designed after observing the large candidate-label differences in `PROTOCOL_order_sensitivity.md`. It is exploratory and uses the same previously selected pools; it is not an independent validation. Its purpose is to probe two explanations that were confounded in the first reversal: changed item order and reassigned product identifiers, with an additional repeat of identical prompts as a limited execution-stability control.

For each of Qwen3-4B-Instruct-2507 and SmolLM2-1.7B-Instruct, reuse exactly the same 250 original ESCI and 160 sampled WANDS candidate pools, final per-query specification or fallback, chunk boundaries, system instructions, example-removed compact prompt, model assets, and guided V1 decoding configuration as the saved `run_guided_compact_*_v1` baseline. The previous `run_reverse_order_*_v1` supplies the reversed order with identifiers reassigned to positions. Save new results without modifying either previous run.

Generate two new conditions, in this fixed order within one engine instance. First, **replay** the exact original candidate order and local product identifiers, using byte-identical user prompts reconstructed from the source data. Second, **reverse with stable identifiers**: reverse the product order inside each existing chunk, but retain each product's original local identifier. Other than that permutation, the input contains the same candidate texts and IDs. The expected answer remains one Y/N per product in the presented order; map labels back to the original candidate positions. A chunk of size one is unchanged. Each model must first pass the incompatible-word regex negative control. Use vLLM 0.10.2 V1, temperature zero, bfloat16, 4,096-token context, maximum 32 output tokens, one RTX 5090, at most 16 concurrent sequences, eager execution and prefix caching. Apply the strict parser and at most one retry per invalid response. Do not impute missing labels.

On pools completed under all four conditions, report candidate-label change fractions, counts of pools with changed labels, and query-macro mean absolute ratio changes for four contrasts: (1) archived original versus replay (identical prompt); (2) replay versus stable-ID reversal (product order changes while each product's displayed ID stays fixed); (3) stable-ID reversal versus the earlier renumbered reversal (product order is the same but ID assignment differs); and (4) archived original versus renumbered reversal. Report completion for every condition, per-condition candidate F1, balanced accuracy, and ratio MAE against each dataset's inherited reference, and 4,000 paired query-cluster bootstrap intervals for the label-change fraction and mean absolute ratio change using a fixed seed. Preserve query identifiers, output strings, source-run identifiers, candidate mappings, prompt hashes and verification results.

These are input-level controlled contrasts, not definitive causal identification: the runs occur in a fixed sequence, inference execution may be numerically nondeterministic, one replay cannot measure all run-to-run variation, and models may interpret numeric IDs in unexpected ways. Changing order also changes prompt context. Report no deployment-scale latency or claim that a particular model family is intrinsically more stable. Positional structure, format validity and agreement do not certify the truth of the inherited relevance labels or real shopper satisfaction.
