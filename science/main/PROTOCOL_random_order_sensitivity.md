# Post-hoc multi-permutation sensitivity on the exposed WANDS holdout

This exploratory check is designed after the original, reverse-order, keyed-output and local-copy replay results were observed. It reuses the same 160 public WANDS holdout queries, their previously sampled 5,120 judged candidates, and the saved query specifications or fallbacks for each of Qwen3-4B-Instruct-2507 and SmolLM2-1.7B-Instruct. It is not a new dataset, blinded confirmation, user-satisfaction study or production benchmark. No selection or permutation depends on reference labels or prior prediction outcomes.

Each query retains its four existing consecutive chunks of eight candidates and the original candidate IDs within each chunk. For each query, chunk start and replicate `1`, `2`, `3`, derive a Python `random.Random` seed from the first eight bytes of SHA-256 of the UTF-8 string `ICDE2027-random-order-v1\0{query_id}\0{chunk_start}\0{replicate}`, interpreted as an unsigned big-endian integer. Shuffle the eight positions with that RNG. Identity and repeated permutations are permitted. Save the full position mappings and verify them independently before inference. Both models use exactly the same saved candidate permutations, with their own earlier saved specifications or direct fallback.

Run Qwen first and SmolLM2 second. For each, run six conditions in fixed interleaved order: `baseline_a`, `perm_1`, `baseline_b`, `perm_2`, `perm_3`, `baseline_c`. Each baseline uses the same original-order prompt. Each permutation preserves the local ID attached to each candidate and requires labels in the *presented* order; map the resulting labels back to original candidate positions. Compare `perm_1` to `baseline_a`, `perm_2` to `baseline_b`, and `perm_3` to `baseline_c`. Also compare the identical-prompt baselines `baseline_b` and `baseline_c` separately with `baseline_a` to show some execution variability. The fixed sequence and only two repeated baselines cannot isolate all runtime effects.

Use the existing locally copied isolated environment, V1, the recorded model and tokenizer hashes, bfloat16, 4,096-token context, eager execution, 0.70 GPU memory fraction, prefix caching, at most 16 concurrent sequences and temperature zero. Use the original WANDS system instruction and compact example-removed prompt, constrain each response to `[YN]{8}` with a 32-token maximum, and permit one format retry using the original retry suffix. Preflight all prompts and possible retries against the context limit. Verify an incompatible ordinary-answer negative control and a guided positive control before model outputs. Require an idle GPU before loading; check process ownership after loading and before each generation batch or retry, and stop only this run if a foreign GPU process appears. Submit at most 64 chunks per generation call. Save each completed batch immediately, including prompt hashes, ID/position mappings, first and final responses, finish reasons, token counts and retry status. Never replace an invalid response by a label.

Analyze all six conditions on pools completed by every condition for a given model, and report each condition's completion separately. For each of the three paired permutation comparisons and both identical-prompt baseline comparisons, report the number and fraction of candidate labels changed, query-macro mean absolute change in the predicted positive ratio, and the number of changed pools. Also report candidate F1 and query-macro ratio MAE against the saved Exact-only relevance proxy for every condition. These are descriptive, unadjusted post-hoc measurements on the exposed sample; do not report a new hypothesis test, causal effect, guarantee or population confidence interval. The label counts and reference judgments are never included in model prompts. Two models differ in size, architecture, tokenizer and generated specifications, so cross-model results cannot identify a single causal factor.

Freeze this protocol, deterministic selection code and saved mappings, preflight and runner, synthetic tests, analysis and independent verifier, the two original specification files, selection inputs, local model and tokenizer hash manifests, and previously observed baseline outputs before inference. Retain all attempts and results, including failures or null effects. Do not overwrite saved outputs or stop other users' processes.
