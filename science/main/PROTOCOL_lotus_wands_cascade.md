# Post-hoc LOTUS filter cascade on the exposed 52-query WANDS sample

This is a post-hoc system reference after all existing WANDS results, labels, model outputs and selective-scheduler outcomes have been observed. It reuses the 52 queries and 1,664 judged candidates in `wands_selective_execution_selection/inputs.jsonl`; it is not a new blind sample, a comparison of entire systems, a production benchmark, or evidence of true purchase satisfaction. The ground truth is the inherited WANDS Exact-only relevance proxy and the model sees only the saved truncated product text.

## Execution, fixed before measured data requests

Flatten the saved 52 pools and record each query ID, candidate ID and original position. Shuffle the 1,664 rows using `numpy.random.default_rng(20271305).permutation` and reset the DataFrame index. Run the real PyPI `lotus-ai==1.2.4` DataFrame `sem_filter` on the shuffled rows, first with the main model only, then with its built-in helper-LM cascade. Both use the same WANDS-oriented natural-language predicate, LOTUS default True/False prompt and parser, no examples or reasoning, temperature zero, 16 generated tokens maximum, `return_all=True`, `return_raw_outputs=True`, default=True, `return_stats=True`, and no LOTUS cache. The LOTUS prompt and parser differ from the saved IntentSat plans; the shuffled order also differs.

Use Qwen3-4B-Instruct-2507 as the main model and SmolLM2-1.7B-Instruct as the helper, each served by its own vLLM 0.10.2 V1 process over loopback HTTP on the same RTX 5090 GPU. Use bfloat16, context 4,096, maximum 16 sequences per server, eager execution, disabled prefix caching, GPU memory fractions 0.49 and 0.28 respectively, and a client batch size of 16. Both models remain loaded during both phases. Local tokenizers must encode each LOTUS output token as exactly one token; check the maximum actual rendered-prompt length plus output cap against both context limits. Model load, server startup and unrelated synthetic warmup are not included in measured phase times.

Use `CascadeArgs` with helper LM, recall_target=0.8, precision_target=0.8, failure_probability=0.2, sampling_percentage=0.1, cascade_IS_weight=0.9, 50 calibration quantiles, random seed 20271231, and `cascade_IS_max_sample_range=1664` so the sampling domain covers all shuffled rows. Thresholds are learned by LOTUS from its main-model sample; they are not tuned on WANDS human labels. The release samples with replacement, so repeated calibration rows are possible. The nominal targets refer to the reference-model procedure, not human-label accuracy; the implementation, dependence, repeated products, finite sample, and fresh model calls prevent treating the targets as proven achieved guarantees here.

## Required trace and analysis

Record the installed wheel version and hashes, prompt text and its SHA-256, main and helper output text, the helper top-logprob traces, the calibrated proxy scores, sampling indices and correction factors, selected thresholds, final Boolean outputs, raw outputs, default/ambiguous parse counts, model batch-call counts, logical prompt and completion tokens, routed row counts and phase wall times. Intercepting the library's LM calls and importance-sampling result is for passive logging only; invoke the original functions and return their results unchanged. Do not record credentials. Record failures rather than silently substituting a model or plan. Sample and fallback oracle requests may overlap and must both be counted. A logical model request count is not a count of any hidden HTTP retries or a monetary cost.

Map all results back to original queries and candidate IDs. Report Qwen-only LOTUS, LOTUS cascade, previously saved Qwen selective fallback and an all-query-words baseline on all 52 pools: candidate F1 and balanced accuracy, query-macro ratio MAE, and completion/parse diagnostics. For cascade minus Qwen-only LOTUS use paired query-cluster bootstrap 95% percentile intervals for F1 and ratio MAE (4,000 resamples, seed 20271306); these intervals are descriptive, unadjusted for repeated comparisons and do not remove product or query dependence. Also report empirical candidate-level cascade-versus-separately-run Qwen-only agreement, precision and recall when denominators exist; Qwen outputs can change between calls, so this does not establish the nominal cascade guarantee.

Phase times include local client assembly, library work, queueing, generation, parsing and trace-file writing, but exclude model loading and warmup. Only one fixed-order run is performed with both models sharing a GPU; these timings are not comparable with earlier offline experiments, internet latency, production throughput or cross-hardware performance. No generalized speedup or accuracy superiority is claimed.
