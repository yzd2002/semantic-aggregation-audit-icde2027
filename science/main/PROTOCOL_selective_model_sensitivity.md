# Secondary model sensitivity for actual selective execution

This follow-up is defined **after observing the Qwen result** and the earlier two-model order audit, but before running the new SmolLM2 outputs. It reuses the exact 52-query WANDS selection used by Qwen; it is not a new sample, a blinded replication or a new data source. Its purpose is to describe whether the same actual selective procedure completes and how its quality behaves under a second, smaller model. Model family, size, tokenizer, chat template and generated specifications change together; no causal architecture comparison or model superiority claim is justified.

## Fixed execution

Verify `SELECTIVE_EXECUTION_FROZEN_SHA256.txt` and reuse its 52 saved queries, 32 sampled judged products per query, WANDS exact-only system instruction and text serialization. Run SmolLM2-1.7B-Instruct using the recorded model/tokenizer hashes, vLLM 0.10.2 V1, bfloat16, temperature zero, one RTX 5090, eager mode, 4,096-token context, prefix caching and 16 concurrent sequences. Generate new SmolLM2 query specifications with the same prompt, 160-token cap, one retry and direct fallback. Do not reuse Qwen's specifications.

Use the same fixed-key JSON grammar and original, within-chunk stable-ID reversal, actual selective pointwise, identical keyed replay and all-candidate pointwise conditions and fixed order as `PROTOCOL_selective_execution.md`. Send a pointwise `[YN]` request only for a valid keyed disagreement in the selective stage; use a four-token cap and one retry. The later full-pointwise outputs are a separate diagnostic, not inputs to the actual selective result. On missing required outputs, abstain for the affected pool, never impute N. Verify the keyed and pointwise constraints against incompatible BANANA instructions before evaluation. Save raw responses, ID associations, first/retry outputs, prompt hashes, token counts, context checks, completion and actual offline batch time. The time excludes model loading, negative controls and later diagnostics; it is one fixed-order offline batch, not online latency or a Qwen-versus-SmolLM2 speed comparison.

## Fixed descriptive analysis

Report completion over all 52 pools and the common-complete subset of original, reverse, keyed replay, full pointwise and actual selective output. On that subset report candidate F1, balanced accuracy and query-macro ratio MAE against Exact=Y and Partial/Irrelevant=N. Describe actual selective minus canonical-keyed ratio MAE with 4,000 paired query-cluster bootstrap draws using NumPy `default_rng(20271202)` and the 2.5th/97.5th percentiles. This is a **secondary descriptive comparison with no pre-specified success threshold**; preserve negative, null or positive outcomes. Also report all-pointwise and all-query-words results, actual selective requests/cost, keyed replay changes, and changes between matched selective and later full-pointwise prompts.

The 1,664 observations contain 1,622 distinct sampled product IDs, 41 repeated across queries. As an additional secondary sensitivity, independently resample the observed query IDs and product IDs with replacement. Within each query weight its candidates by sampled product multiplicity, compare the absolute ratio errors of selective and canonical output, and take the query-multiplicity-weighted average. Use 4,000 draws and NumPy `default_rng(20271203)`, sampling query indices before product indices and failing if a selected query has zero product weight. Sort product IDs numerically. This pigeonhole-style sensitivity follows the procedure in `PROTOCOL_selective_two_way.md`, inspired by Owen (https://arxiv.org/abs/0712.1111); it reweights candidate pools and is not exact coverage for the fixed-pool target. Products are sampled conditional on queries, the same public source and sample are reused, and relevance labels are not shopper satisfaction.
