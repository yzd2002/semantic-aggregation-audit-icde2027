# Post-hoc LOTUS semantic-filter comparator (before its evaluation)

After observing the earlier Qwen, SmolLM2 and supervised-baseline results, run the published LOTUS `sem_filter` operator on the same 250 original labeled ESCI query pools. This is a post-hoc systems reference, not an independent dataset, a benchmark of the full LOTUS optimizer, or a controlled test of prompt/architecture differences.

Use LOTUS PyPI release `lotus-ai==1.2.4`, the `LM` backend pointed only at a loopback vLLM server, the same local Qwen3-4B-Instruct-2507 weights, bfloat16, 4,096-token context and at most 16 concurrent sequences on the same RTX 5090. Set model decoding temperature to zero and maximum 16 generated tokens; these limits, the operator prompt, the served API and batching differ from the offline plan runs, so elapsed time and output differences do not isolate a system effect. Use no cascade, examples, helper model or reasoning mode. Each of 5,160 candidate rows contains the saved query text and the same truncated product text. The predicate asks whether the product is an exact match or functional substitute for the query, excluding accessories or unrelated products and assuming no unstated properties.

Call the actual library `DataFrame.sem_filter` with `return_all=True`, `return_raw_outputs=True`, and the release's standard `default=True`. Save every raw response and LOTUS Boolean decision. The release's parser looks for the positive token first, then the negative token, and uses `default=True` if neither occurs. Count unresolved/ambiguous raw outputs separately: report defaults and responses containing both decision tokens instead of silently claiming that every returned Boolean is structurally validated. A pool is structurally complete under a separate strict check only if each candidate raw response has exactly one of the two decision tokens; do not overwrite the system's actual Boolean output. If execution fails, report the error and do not fabricate results.

For each of all 250 pools and the 207 Qwen-four-plan common subset, compute candidate-level F1 and balanced accuracy, query-macro ratio MAE, query-cluster bootstrap intervals (4,000 draws, seed 20271109), and paired intervals for LOTUS minus the Qwen pointwise plan on identical query pools. Record request configuration, prompts/instruction, version and raw decisions. Do not treat online API wall time as comparable with the earlier offline-generation timer or claim the test covers LOTUS cascades, calibrated optimizations or other workloads.
