# Post-hoc keyed-JSON ordering audit on the previously exposed WANDS holdout

The original compact-output prompt requested one character per product in the **listed order**, and the recorded reversal was parsed accordingly. After inspecting those results, an alternative explanation was identified: a model might emit answers in numeric-ID order despite that instruction. For the already observed Qwen holdout, interpreting the reversed compact string as ID-ordered instead of listed-ordered changes the apparent replay/reverse disagreement from 1,733/5,120 to 1,475/5,120; for SmolLM2 it changes 643/5,120 to 271/5,120. This counterfactual decoding violates the recorded prompt contract. It is a diagnostic of output-association ambiguity, not evidence of the order the model intended, and must not replace the original result.

This follow-up is exploratory and reuses the already exposed selection and model-specific specifications; it is not a fresh confirmation of the 10% threshold or an independent data source. The goal is to test an alternative execution contract that explicitly keys each judgment by its product ID, not to claim an intrinsic language-model position effect.

## Setup fixed before these new inferences

For each model, load exactly the saved 160-query WANDS holdout selection and that model's saved specification/fallback for each query. Reuse the eight-product chunks, product texts, local IDs and WANDS task system message. For three conditions in fixed order—original, identical-prompt replay, and stable-ID reversal—present the same candidates while preserving the ID attached to every product. The first two prompts must be byte-identical. Reversal changes only the order of the eight serialized product lines. The additional instruction explicitly requests a JSON object mapping the *given ID*, not position, to Y/N; all keys must appear exactly once in increasing numeric order. The byte-exact regular expression forces the fixed keys `1` through `8` and Y/N values. Parse by key into the original product positions in all conditions. This makes the parser's intended association unambiguous, but cannot prove that the model semantically associated each label with the correct product.

Use vLLM 0.10.2 V1, the original model and tokenizer paths and hashes, bfloat16, temperature 0, eager mode, one RTX 5090, context limit 4,096, prefix caching and 16 concurrent sequences, with a 128-token cap and one retry for any invalid response. Do not regenerate specifications. Before evaluating candidates, independently generate a BANANA instruction with and without the same keyed regex and require that the former violates and the latter obeys the keyed format. Save all first and retry responses, finish reasons, prompt hashes, mappings, format checks and incomplete pools. Fail closed on negative-control failure. Do not impute missing labels. The context check includes the retry suffix and output cap.

## Analysis fixed before these new inferences

Report for each model: completion by condition; counts and fractions of candidate labels changed by replay and reversal on the three-condition common-complete query pools; per-query mean absolute pool-ratio change; candidate F1, balanced accuracy and per-query ratio MAE against the Exact-only WANDS relevance proxy; and 95% query-cluster bootstrap percentile intervals from 4,000 draws using NumPy `default_rng(20271125)`. Compare the keyed and prior compact results descriptively on their common pools, but the prompts, output grammars, length caps and execution instance differ, so this does not isolate any single causal mechanism. Preserve the original prompt-contract parsing and its pre-specified holdout analysis unchanged.

In an explicitly post-hoc diagnostic of the old compact strings, compare the original/replay answer with the reversed string under both the instructed listed-order decoding and a counterfactual numeric-ID-order decoding, and report their fractions on the same pools. Identical strings, labels and aggregate ratios need not imply correct judgments; differing output assignments can arise from instruction following, content interactions, context, ID association or execution effects. The data are already exposed, two models share a source, only one replay is used, and all intervals are descriptive for this selected sample. No causal interpretation, semantic validity, calibrated coverage, general population rate or deployment claim follows.
