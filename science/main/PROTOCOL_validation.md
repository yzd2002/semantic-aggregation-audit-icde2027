# Disjoint validation protocol (frozen before the second experiment)

The initial 160-query study showed lower recall and higher offline generation time for indexed-JSON listwise plans, and seven unresolvable query-only specifications. Those test results motivated a compact output contract and a fallback when a specification cannot be validated. To avoid evaluating the new design on the same queries, draw 500 distinct query strings from the remaining eligible strings in the same published test split, excluding every string in run_test_160/inputs.jsonl. This is a disjoint query-text holdout within one dataset; it is not an external dataset or a replication across models. All data transformations and labels match PROTOCOL.md, except for sample seed 20271101.

Compare five plans on the same pools: pointwise, indexed-JSON batch, indexed-JSON two-stage, direct compact-code batch, and two-stage compact-code with fallback. The first three repeat the prior prompts. The compact format asks for exactly n contiguous Y/N characters in the input order; strict length/alphabet validation is required, and an invalid response gets one retry. This checks output length and syntax but does not prove positional semantic alignment. The two-stage compact plan attempts the same validated specification twice. On failure it issues the direct compact prompt and records a fallback; it does not invent a specification. All plans use the same decoding, hardware, truncated texts, and candidate pools; generated token caps are 4 (pointwise), 192 (indexed JSON), 160 (specification), and 32 (compact). Metrics and attempt-denominator accounting match PROTOCOL.md. Per-method timings include model generation, retries and any fallback, but exclude model load and Python bookkeeping; offline throughput is scheduling-dependent. Report pilot results separately, and report 500-pool results without modifying prompts in response to them.

## Post-hoc analytical checks

After the validation run, we additionally computed all-Y and all-N constant predictors on the same common completed pools, and balanced accuracy, to assess the influence of the constructed class mix. These descriptive baselines were added after inspecting the observed outcomes and are not a pre-registered model comparison. Their inclusion does not alter the sampled pools or any LLM responses.

**Timing clarification:** The recorded interval includes chat-template rendering as well as the batched generation call; it excludes model loading and most other Python-side prompt assembly and parsing.
