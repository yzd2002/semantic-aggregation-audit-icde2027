# Post-hoc WANDS embedding input-token accounting

The original post-hoc embedding experiment encoded the 160-query training sample and three already exposed WANDS test samples jointly. It recorded the number of query vectors, the number of distinct product-text vectors, and the maximum non-padding token length, but did not save the total or per-input token lengths. Table VII excludes that encoder work from its generation-call accounting. This is an after-the-fact accounting reconstruction, not a new model inference, speed benchmark, validation set, or test of model quality.

Reconstruct the query strings with the exact prefix and the first-occurrence deduplicated candidate text sequence by following the recorded sample order and original code. Check the entire reconstructed index mapping against the saved mapping and the four saved sample sizes. Load the local pinned tokenizer.json using tokenizers 0.22.0, disable truncation and padding, and use the saved special-token postprocessor. Hash the tokenizer files, four sample inputs, saved mapping, original encoding script and saved embedding summary; insist on the original recorded tokenizer and config hashes. Verify each sequence ends in model-config EOS 151643, that the reconstructed number of queries/documents and the maximum non-padding length exactly match the original summary, and that no length exceeds the original cap. Sum attention-mask-equivalent lengths over each query and first-occurrence text once, and also sum the batch-of-32 padded tensor positions. The latter is a tensor-shape accounting number, not physical work, model FLOPs or compute actually expended.

For each test sample separately, report the number of unique sample-local query and document strings and their reconstructed unpadded token totals. Those are hypothetical isolated encodings; the recorded run encoded all four samples jointly, deduplicated globally and used fixed batches, so neither sample-local counts nor proportions of total runtime were measured. Different tokenizers, model architectures, batching, padding, caching, preprocessing, hardware and training costs make the encoder's token totals unsuitable as direct latency, energy, FLOP or dollar comparisons against the generative models. Retain the original joint elapsed time and GPU peak only as originally recorded.

Independently re-tokenize all strings using the original transformers 4.57.1 AutoTokenizer interface, also with the fixed local tokenizer, matching every reconstructed per-sequence token length, EOS and token ID digest; this is an independent interface check, not an independent tokenizer implementation or a hardware reproduction. Both checks run on CPU only, without loading model weights or generating labels. Preserve results and clearly label the post-hoc reconstruction. Do not alter the original frozen protocol or claim token totals were logged by the GPU run.
