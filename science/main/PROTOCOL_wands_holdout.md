# Query- and sampled-product-disjoint WANDS holdout (frozen before inference)

This follow-up was designed after observing the earlier WANDS and ESCI order-sensitivity results. It uses **new queries and sampled products from the same public WANDS dataset**, not a new independent data source or a human purchase study. Its aim is to test whether the pre-specified within-chunk ordering result persists on an unobserved sample without changing the task or tuning against its outcomes. Model pretraining exposure to WANDS is unknown.

## Frozen selection

Verify the three source SHA-256 hashes and the revision documented in `WANDS_DATA_SHA256.txt`. Require unique source query/product/annotation keys and valid foreign keys. Collapse repeated identical query–product labels to their minimum annotation ID, and remove all query–product groups with conflicting grades, as in `PROTOCOL_wands.md`. Normalize query text by trimming and case-folding. Exclude normalized query strings used in all three prior ESCI samples **and** in the earlier 160-query WANDS sample. Also exclude every product ID included in that earlier WANDS sample; this is disjointness from the *sampled* products, not evidence of exclusion from model pretraining or all prior source tables. Require distinct nonempty normalized remaining query strings and at least 32 remaining nonconflicting judged products. These exclusions and eligibility conditions are applied before sampling without using grade proportions.

Sort the eligible query IDs and uniformly sample 160 without replacement with Python `random.Random(20271122)`. For each selected query, sort its remaining candidates by numeric annotation ID and product ID; sample 32 without replacement with a query-specific RNG seeded by the first eight bytes of SHA-256 of `20271122`, a NUL, and the decimal query ID; shuffle the sample with that same RNG. Save original query, annotation and product IDs, texts, grades, gold mapping and resulting order. Verify query-string and product-ID disjointness from the prior sampled WANDS data and query-string disjointness from the prior ESCI samples. No grade stratification, product-quality filtering, label-dependent threshold tuning or outcome-driven replacement is allowed. Reproduce the selection independently from the pinned raw source.

## Fixed inference

Use the original WANDS exact-only proxy: Exact=Y, Partial/Irrelevant=N, with the same task-specific system instruction and text serialization as `run_wands.py`. For each of Qwen3-4B-Instruct-2507 and SmolLM2-1.7B-Instruct, execute on the **same** 160 saved pools in a new output directory. Use vLLM 0.10.2 V1, temperature zero, bfloat16, maximum context 4,096 tokens, one RTX 5090, eager mode, prefix caching, at most 16 concurrent sequences and the recorded model/tokenizer hashes. First run the incompatible-word negative control to verify the Y/N regex constraint. Generate one query-only specification using the existing specification prompt, 160-token output cap, strict parser and one retry; if it remains invalid, use the existing direct-compact fallback. Retain every specification response and fallback flag.

With that fixed specification or fallback, split each pool into the existing consecutive chunks of eight. Generate three compact, example-removed, regex-guided conditions in this fixed order: **original**, an identical-prompt **replay**, and **stable-ID reversal** (reverse product order inside each chunk while retaining each product's original local identifier). Reassign neither products across chunks nor identifiers to new products. Require exactly one Y/N character per presented product, maximum 32 output tokens and one retry after an invalid response. Map reversed labels back to original candidate positions and retain every raw output, first/retry result, prompt hash, candidate mapping, context check and completion decision. Fail closed if the negative control fails; do not impute missing decisions or discard failed pools from the completion denominator.

## Frozen analysis and interpretation

The single **primary confirmatory contrast** is the Qwen candidate-label change fraction between replay and stable-ID reversal, on their common-complete pools. Compute a two-sided 95% query-cluster bootstrap interval with 4,000 resamples and seed `20271123`; the pre-specified practical threshold is **10%**, chosen after the earlier results but before this holdout was sampled or inferred. Report whether the interval's lower endpoint exceeds 10% as a benchmark-specific replication criterion, not a population guarantee or an automatic publication claim. Report the numerator, candidate and query denominators, the number of pools with any changed label and the query-macro mean absolute change in estimated ratio. Separately report original-versus-replay differences; one replay does not characterize all numerical run variability.

The SmolLM2 result is a secondary model-sensitivity analysis, using the same selected pools and contrasts. For each model, report completion for all 160 attempted pools, pooled candidate F1 and balanced accuracy, and query-macro ratio MAE on the three-condition common-complete subset. On that same subset report deterministic all-Y, all-N and all-query-words baselines. Report exact grade distribution, specification fallbacks, prompt and token limits, and all query-cluster intervals; do not treat a correct format, agreement, F1, or the 10% criterion as proof of semantic correctness or deployment readiness. Query sampling and removal of previously sampled products affect the workload, reference labels are relevance proxies, and annotators saw richer product information than the model. Runs occur in a fixed order; they change product sequence and prompt context and may be affected by numerical execution. Preserve all negative results and avoid a general causal architecture claim.
