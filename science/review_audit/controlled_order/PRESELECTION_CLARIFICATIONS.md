# Preselection implementation clarifications

Recorded on 2026-11-02 before selecting the 128 ESCI queries or generating any new data judgments. These clarify the root agent's frozen protocol; neither model's new outcomes have been observed.

- Exclude an entire ESCI query ID if any of its candidates has a prior ESCI/training product ID or exact visible 600-character text. Never remove overlapping candidates and keep the shortened pool. Normalize queries only by `strip().casefold()`. Prior visible text is `text[:600]`; training text is reconstructed from the pinned US product table by joining nonempty string fields in the established five-field order, then slicing 600 characters. Union every prior ESCI inputs file and both supervised train manifests. Prior derived pools lack product IDs; their observed query/text exclusions are retained without claiming recovered IDs. All prior WANDS inputs contribute normalized query exclusions. Save every exclusion-source path and hash and whole-query exclusion counts.
- Each selected candidate keeps its original one-based pool occurrence ID across all chunks, row permutations, and singleton runs. Output keys are sorted numerically, not lexicographically.
- The complete dataset/chunk/condition/repeat/singleton schedule, execution ordinal and 64-request block membership are frozen and hashed before either model's new judgments. Identical schedule bytes are shared between models.
- For each ascending/descending output order, the co-primary descriptive quantities are BOTH excess candidate disagreement and excess absolute ratio change (row-order contrast minus same-condition replay, with negative values retained). Report both output orders and their effect-modification differences for both quantities. Candidate-level significance cannot substitute for a ratio-level conclusion.
- Both output-order primary estimates and their difference use the same intersection of pools complete in all eight batch condition/repeat vectors. Never average over only the successful repeats. Batch quality comparisons also use this all-eight-complete set; completion always reports every attempted/selected pool. Batch–singleton comparisons additionally require both complete singleton vectors, and report that common set and exclusions. Report singleton quality separately and on the shared comparison set. If execution terminates early, distinguish unattempted jobs from invalid returned judgments.
- The inherited same-machine environment is permitted only after grammar negative controls and synthetic smoke pass. Record actual packages and pip-check conflicts; no global dependency changes and no claim of a fresh environment.
