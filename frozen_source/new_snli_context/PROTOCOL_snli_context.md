# SNLI complete-pair fixed-target context audit — prospective protocol

Status: fixed before feature selection and before any new SNLI model judgment. The prior manuscript and context-audit outcomes are already exposed. This is a prospective extension to a third predicate, not preregistration of the earlier work. CPU preparation and independent review must finish before an explicit inference authorization. No GPU inference is authorized by this file.

## Question and source gate

Test whether replacing the other records changes a fixed target's binary entailment judgment when its complete premise and hypothesis, local ID 1, first input position, and target-output prefix stay fixed. Y means that the premise entails the hypothesis; N combines the original neutral and contradiction categories. Every record is judged only from its own premise/hypothesis. This is a tuple-local execution-contract audit, not a new NLI algorithm. A binary collapse does not measure three-class SNLI accuracy.

Use SNLI 1.0 from the public `stanfordnlp/snli` repository, immutable revision `cdb5c3d5eed6ead6e5a341c8e56e669bb666725b`, configuration `plain_text`, complete labeled public test split for targets and train split for background. The Parquet distribution has 10,000 test and 550,152 train rows and fields `premise`, `hypothesis`, `label`; native SNLI pair IDs and individual annotator votes are absent, so source IDs are stable split plus zero-based Parquet row index. Never call this a hidden-label test.

The fixed Stanford repository card declares CC BY-SA 4.0 and credits content from Flickr 30k. Preserve attribution, the license link, and the same license for redistributed SNLI text/adapted data; identify the binary-label and feature-wrapper changes. This is a report of the publisher's declared license. The local network cannot retrieve the Stanford project page or original ZIP. Data are transported through the third-party `hf-mirror.com` resolver and public Hugging Face Xet CDN, with downloaded SHA-256 and size checked against fixed Git LFS pointers/tree metadata. Do not claim direct byte comparison with the official ZIP. Record original source URLs, actual transport URLs without signed queries, retrieval times, failures, hashes, license-card lines, and the Bowman et al. 2015 ACL paper. Validation split is not used.

Root seed is **2026110611**. Use SHA-256 of `seed|reserve|source_id` for test reserve order and `seed|bank|source_id` for background-bank order. Domain-separated deterministic Python PRNG seeds `seed|context`, `seed|schedule`, and `seed|serial` control proposal, main and serial schedules. ## Label-blind eligibility and reserve

The only label-dependent eligibility metadata is whether a row has a valid original label in {0,1,2}; exclude -1/no-label and unexpected metadata values. Do not inspect the label category for selection, balance classes, use confidence/votes, or consult model outputs. Drop malformed/non-string/empty fields. For valid rows, compactly serialize the **complete** `{premise,hypothesis}` feature object and require at most 512 tokens under **all three** local tokenizers. Record full-dataset feature lengths and every exclusion; no token truncation.

Sort eligible test rows by the reserve hash, then greedily reserve 256 rows whose normalized complete premise and hypothesis strings have not appeared in either role in earlier reserved rows. Normalization is Unicode casefold plus whitespace collapse. Preserve original strings for prompts. This is seeded hash-order sampling with an observed-text non-overlap rule, not a uniform sample of all possible independent pairs. Abort before inference if the reserve cannot reach 256.

Exclude every train row sharing any normalized complete premise or hypothesis in either role with **any of the 256 reserved rows**, including unused reserve rows. Feature-deduplicate the remaining eligible train records by normalized ordered premise/hypothesis, retaining the first source ID in deterministic source-ID order. Then sort by the feature-only bank ID hash and keep at most 10,000 records. Record pre-cap counts, exclusions, retained IDs and cap order. This is a lexical/observed-text safeguard; it does not exclude latent semantic overlap or unknown model pretraining exposure.

## Context construction and feasibility

Fit raw-count word unigram/bigram TF-IDF on the capped background bank only, with Unicode regex `(?u)\b\w+\b`, lowercase, smoothed IDF `log((1+n)/(1+df))+1`, L2 normalization and no label features. Search each target's complete compact feature serialization. Greedily take the top three cosine-ranked rows, with source-ID tie breaks, forbidding repeated normalized premise/hypothesis across either role within the triplet.

For each near position draw a random background row uniformly from the remaining pool whose serialized feature token length differs by at most w in every tokenizer. Exclude the near triplet's full-text identities and all repeated fields within the random triplet. Try w=16, then 32, then 64; at most 2,000 seeded proposals per width. Accept the first random triplet whose complete wrapped prompt differs from the near prompt by at most 24 tokens in **each of the three tokenizers and every output scope**, and whose prompt plus 128-token cap stays within 4096. Do not select or reject using similarity thresholds, gold categories or model judgments. Save all proposal IDs, lengths, statuses and accepted similarities.

Visit reserve rows in fixed order and retain the first 128 feasible targets. Check singleton caps separately. Do not infer until exactly 128 pass; if fewer pass, stop and report a feasibility shortfall without relaxing criteria after judgments. The bank remains fixed after excluding all 256 reserve rows. Save unused reserve IDs and rejection reasons.

## Requests, schedules, and controls

Every contextual prompt lists target ID 1 first, followed by the chosen ordered background IDs 2,3,4. For each near/random context, run full-first, target-only, and full-last twice. Full-first requests IDs [1,2,3,4] and emits grammar keys 1,2,3,4. Full-last uses **byte-identical prompt and token IDs** to full-first, including the requested-ID list, with grammar keys 2,3,4,1. Target-only has all four input records but requests/emits only ID 1. Also run two singleton references with only the target input. There are fourteen calls per target/model: 1,792 main calls per model.

Freeze one seeded shuffled main schedule shared across all models, with submission blocks of at most 64 and at most 16 engine sequences. For selected ordinals 0–31 only, freeze a separate shared shuffled serial schedule copying exactly the fourteen main requests per target, including prompt bytes, token IDs, caps and grammars. Serial runs follow the complete mixed main run on the same loaded model, one blocking generation call at a time. Serial adds 448 calls per model. Execution order/history differences remain a limitation; this is a secondary sensitivity check.

Before scientific calls, freeze and run exactly 20 diagnostic requests per model: one unguided BANANA incompatible-instruction control, five guided versions with key sets [1], [1,2,3,4], [2,3,4,1], [9,10,11], [11], and fourteen synthetic-format requests (two fixed synthetic panels times the seven context/scope combinations). Gate only strict format and incompatible-guidance behavior, not the semantic predictions on synthetic items. Every raw string is retained untrimmed. Strict grammar admits only exact compact JSON, quoted IDs and quoted Y/N values, correct ordered keys, no whitespace, explanation, duplicate/extra/missing keys or partial salvage. Preparation freezes positive and negative parser examples.

Cost commitments: per model 1,792 main + 448 serial = **2,240 science calls**, plus **20 diagnostics**. Three models total **6,720 science + 60 diagnostics = 6,780 calls**. Each main model emits 4,864 requested scientific label slots; serial emits 1,216; science total 6,080/model and 18,240 across models. Diagnostics constrain 51 Y/N slots/model (153 overall), plus one unconstrained BANANA output/model. These are planned requested slots, not observed valid answers or measured tokens. Prepared requests and an append-only ledger determine exact planned input tokens; actual input/output tokens, timings, failed attempts and all diagnostics must be counted after inference. No online speedup claim follows from mixed timings.

## Primary and secondary estimands

For target t and scope s, let a1,a2 be near binary decisions and b1,b2 random decisions. Replacement is `(I[a1!=b1]+I[a2!=b2])/2`; replay is `(I[a1!=a2]+I[b1!=b2])/2`; target excess is replacement minus replay. Primary is the mean full-first excess for each of the three models. Retain negative and null results. Report a descriptive 95% percentile target-bootstrap interval and the predeclared **98.75%** interval with quantiles [.00625,.99375], 4,000 draws, linear quantiles. Positive-primary-evidence criterion is a 98.75% lower endpoint >0. Three new primary contrasts each have nominal alpha .0125; the Bonferroni bound .0375 is conservative relative to .05 for this new family. Do not divide .0125 by three, and do not claim a single unified FWER with earlier tasks. Bootstrap intervals are approximate descriptions on the selected target sets, not guaranteed population/causal coverage or an exact test.

Target-only and full-last excess, their paired differences from full-first, signed near-minus-random reference-error differences, singleton comparisons, serial/mixed comparisons on the identical 32-target subset, and stable changes with individually stable replays are secondary with unadjusted 95% intervals. The prior four-call reference qualification (two singleton plus two random/full-first agree) and near-context any/stable transport failures are secondary, with all denominators and invalid outcomes retained; no fitted threshold or deployable optimizer claim.

Attach original labels and binary mapping only after feature selection and an executed gold-perturbation invariance test. Perturb every valid source category by a fixed cyclic mapping 0→1→2→0 (invalid metadata unchanged), rerun selection from freshly loaded features with reset RNGs, and require identical selections, proposals, prompts and schedules. Gold-quality reporting uses the original public reference labels, original-class counts and no class-based exclusion. Report target condition error, F1, balanced accuracy, confusion counts, constants all-Y/all-N, singleton quality, and wrong-to-right/right-to-wrong changes separately. No individual annotator vote confidence can be assessed from this Parquet distribution. Public labels and SNLI annotation artifacts/pretraining exposure limit interpretation.

## Completion, COUNT and audit ledger

Record all scheduled, submitted, returned, valid/invalid and unreturned scientific/diagnostic calls. Main paired analyses use the common target set complete across twelve contextual requests; singleton comparisons additionally require both singleton outputs. Report selected and common counts. Preserve every condition and failure, with no silent reruns, replacements, answer-based stopping or favorable-condition selection. A technical repair requires an append-only amendment and retained failed attempt before any resumed call.

For main COUNT/ratio, all 128 selected targets form **one fixed logical relation**; serial uses the separate fixed 32-target relation. Background labels never enter either relation. First sum aligned target predictions, then report positive count/ratio, signed and absolute count change/error, both directions, reference-free flip cancellation, and reference-error cancellation. Emit each aggregate only when every target in its fixed relation is valid in the relevant condition; otherwise abstain and retain the fixed denominator. Do not turn average per-target absolute changes into an aggregate COUNT result.

Freeze protocol, code, source/license/model identities, complete selection, complete prepared main/serial/control requests, schedules, alpha allocation, gold mapping/quality definitions, COUNT definitions, parser/preflight checks, planned costs and initial call ledger before the first new model judgment. Independent review must verify target identity/first position and token prefix, all-model length matching/caps, full-first/full-last byte equality, serial copies, strict parser, feature-only selection and exact call/label totals. At CPU handoff, the ledger must show zero attempted judgments and an explicit NO_GPU_GO status.

Interpret stable full-first excess as evidence that preceding generated background labels are unnecessary for the observed selected-target sensitivity. It does not identify attention, reasoning, contamination or a token-level mechanism. Nearest/random differ beyond matched lengths; there is no unconditional semantic-similarity causal claim. Serial persistence shows concurrent submitted requests are unnecessary for that observation; disappearance does not identify the scheduler as its cause. This extends to complete sentence-pair entailment and a third family, while remaining a small fixed-target, fixed-runtime audit.
