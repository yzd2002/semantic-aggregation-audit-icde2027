# Fresh three-family fixed-target context replication

Built with glm-4. The GLM model license is included in LICENSE. Qwen and Smol model license evidence is preserved separately in provenance.

## Timing and scope

This new follow-up was designed after the earlier Qwen/Smol context results and the Qwen/Smol/GLM decision-audit results were known. It is not a preregistration of the original research. All three families will receive entirely fresh context-audit inference in the current recorded runtime. No old model judgment is used as a new near, random, singleton, replay, main or serial observation. New model judgments have not occurred at the final CPU freeze. CPU diagnostics, local file verification and input-length observations are distinguished from model inference throughout the records.

The initial plan was an exact GLM-only transport of the old contexts. Its CPU tokenization report and exact compiled inputs are retained under historical_context_arm and initial_cpu_preflight. The local GLM tokenizer exposed length differences above the original 24-token bound for 34 fixed targets. MATCHING_AMENDMENT_20261106.md records the root-authorized forward amendment, fixed before any new model outcome. The scope was then expanded before inference to a fresh replication in all three families on the identical jointly matched contexts. The GLM-only initial envelope is retained as a superseded CPU preparation; the final authoritative scope is this protocol and the final three-model REQUEST_ENVELOPE.json.

The question is whether replacing other input records changes a fixed target decision beyond its repeat disagreement, including when no background label is generated before the target label. This is an execution-contract audit of complete-field bibliographic matching and passage-conditioned Boolean QA, not a new matching/QA method or a claim about an internal reasoning mechanism.

## Fixed sources, targets and contexts

Preserve the original source exports and selection records without truncating any field. They are not reselected using the now-known model outcomes. Unknown pretraining overlap and latent entity/topic overlap remain limitations.

Every family uses the same 128 fixed targets in each task and exactly the original three near records in their original order. All 256 target identities, selected ordinals and complete feature strings remain fixed. For 222 targets the original random triplet is retained. For 34 targets (4 DBLP–ACM, 30 BoolQ), only the primary arm's random triplet is redrawn. The proposal procedure uses the preserved public training banks, original observed-identity exclusions and per-position feature-length strata, extended to all three exact local tokenizers. Its new fixed seed is 2026110603; it tries widths 16, 32 and 64, with at most 2000 proposals at each width. At each position it draws uniformly among remaining eligible candidates, excluding every near identity and identities already drawn in the random triplet. It accepts the first whole triplet with every complete feature at most 512 tokens and full near/random prompts differing by at most 24 tokens for every scope in all three wrappers, with prompt-plus-128 at most 4096. It never reads gold or model judgments. All 44 attempted proposals, including rejections, are retained; all 34 targets succeeded without dropping or replacing a target or near record. An actual gold-inversion replay reproduced the identical feature-only chosen IDs and full proposal logs. Original random triplets are preserved for the secondary historical arm.

The same task system instructions and unwrapped record/ID/output-scope instructions are used in all families. Only the models' native chat wrappers and tokenizer IDs differ. The target is always the first input record at local ID 1; three background records are local IDs 2, 3, 4. Within each model, task and target, its complete feature text, byte position and token prefix are unchanged across near/random and contextual output scopes. Full-first and full-last prompts are byte/token-identical and differ solely in grammar order. Full-first and target-only fix the literal output prefix before the target label to `{"1":"`. Native GLM slow-tokenizer offsets are reconstructed from exact byte pieces and literal special tokens, verified by complete prompt-byte reconstruction; the other two models use their original fast-tokenizer offsets.

## Requests, independent fresh model runs, and sharing

For each target and model, the primary mixed run uses two repeats of each near/random scope: full-first output IDs [1,2,3,4], target-only output ID [1], and full-last output IDs [2,3,4,1]. Two singletons request ID [1] from only the target input. The fourteen requests per target total 3584 primary mixed requests per model. The original seeded schedule and blocks of at most 64 are preserved. The engine allows at most 16 active sequences, without prefix caching. This scope intervention changes the requested output contract as disclosed; it is not a pure internal-computation mediation intervention.

The serial subset is the original selected ordinals 0..31 in each task, fixed before outcomes, for 64 targets total. Its fourteen requests each are byte/token/grammar-identical to the corresponding primary mixed requests. The original separately seeded serial schedule is preserved, with one prompt per blocking generate call on the same loaded engine. It adds 896 requests per model.

The exact historical-context arm is secondary. For the 34 redrawn targets it adds the original random triplet for all three scopes and both repeats: 204 mixed requests per model, shuffled with fixed seed 2026110604 and submitted in blocks of at most 64. For the 11 such targets in the serial subset (1 DBLP–ACM, 10 BoolQ), it adds 66 serial requests shuffled with seed 2026110605 and submitted singly. The historical arm shares the same new near/singleton calls and all identical new primary calls for the 222 unchanged-random targets. It never shares observations across model families or with old runs. HISTORICAL_SHARED_CALL_MAP_<model>.jsonl links every historical logical request to its one unique new raw observation. Sharing does not create independent observations or additional inference calls.

Execution order within each loaded model is: 20 original diagnostics, primary mixed 3584, historical-extra mixed 204, primary serial 896, historical-extra serial 66. This preserves the complete primary mixed run before either serial stage and discloses the intervening historical mixed work. Serial follows mixed and therefore differs in runtime history and order; it is a sensitivity study, not a scheduler causal experiment or an online latency comparison. Physical GPUs may differ across models according to explicit root allocation, and are recorded; model-family differences are not a pure model-only causal comparison.

The exact per-model budget is 4750 scientific requests, 12970 scientific item labels and 20 diagnostics, for 4770 unique model calls. All three fresh runs total 14250 scientific requests, 38910 scientific item labels and 60 diagnostics, for 14310 unique calls. The 20 diagnostics are the original ordinary BANANA call, five incompatible-instruction grammar calls and fourteen complete-field synthetic format checks. Their semantic judgments do not gate model/task retention. Their strict format and guidance checks are technical gates before scientific inference; failures and all attempted controls remain recorded. No output-based retries, stopping, prompt changes, model substitutions or target replacement are allowed.

## Estimands and complete reporting

The original analyze.py and secondary.py are used byte-for-byte, with their statistical helpers unchanged. For each scope, each target's replacement disagreement is the average of the two aligned near/random repeat disagreements; replay is the average of near and random within-context repeat disagreements; replacement excess is replacement minus replay. Report negative values and all conditions. The primary estimands are the full-first excesses for each of the six fresh task/model combinations. Keep the inherited 4000 shared-index target-bootstrap draws, seed 2026110204, selected-ordinal order, linear percentiles, descriptive 95% intervals and the original 98.75% interval/lower-endpoint-greater-than-zero criterion. The retained 98.75% criterion is an inherited conservative per-comparison threshold relative to 95%; this protocol does not claim a unified six-comparison FWER guarantee, or retroactively combine old and fresh runs into such a family. Failure of the criterion establishes neither no effect nor equivalence.

Retain all original target-only/full-last excesses and paired scope differences, signed reference-error differences, wrong-to-right and right-to-wrong counts, constant all-Y/all-N quality, complete-field singleton comparisons, error/F1/balanced accuracy, and both reference-free and correctness-dependent COUNT cancellation diagnostics. All contextual candidate comparisons use common12 completion; singleton comparisons additionally require common14. Attempted, returned, valid, incomplete and missing counts remain explicit. For COUNT/ratio, each task's 128 selected targets form one fixed relation; backgrounds never enter it and any missing target causes that condition to abstain. The fixed serial relation contains 32 targets per task. Never turn mean per-target absolute changes into an aggregate COUNT result or silently change the denominator.

All historical-context, paired primary-minus-historical, serial and reference-transport results are secondary, with unchanged 95% bootstrap functions and explicit common denominators. Historical comparisons are dependent because identical calls are shared. Also report the fixed original-GLM-length-pass subset descriptively (124 DBLP–ACM and 98 BoolQ targets; corresponding serial subsets 31 and 22); this does not replace the all-target primary analysis. Derived historical/subset views are explicitly marked as observation lookups, with unique raw-call provenance and canonical logical schedules; their reference counts are not added to actual model-call costs. Actual costs come only from the four unique raw scientific ledgers and diagnostics for each model.

Technical failures require append-only reporting and a separately reviewed version before repair; preserve every attempt. No successful, null or adverse result may be omitted based on a desired review score. Reanalysis must operate from saved untrimmed raw strings without model inference. CPU checks include arithmetic truth tables, negative excess retention, invalid/empty denominators, strict parser rejections, serial identity, all-field/source identity, finite rematch replay, and shared-call projection/accounting. Scientific output timings are descriptive; do not claim a deployable optimizer or online speedup.

Context sensitivity in full-first does not require earlier generated background labels for that observation; persistence in serial does not require other simultaneously submitted requests. Neither identifies internal attention/reasoning or a sole scheduling cause. Near/random contexts can differ beyond lexical similarity and length; scope contrasts concern whole requested output contracts. Evidence is bounded to these two complete-field tasks, fixed selected targets, three families and recorded runtime/GPU allocations.
