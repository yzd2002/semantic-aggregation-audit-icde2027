# Technical startup amendment 0002: local inspection callable transport

Qwen and Smol attempt02 loaded their model weights, then terminated before the first diagnostic generate call because the native vLLM V1 utility serializer rejects a Python function by default. The frozen call is llm.collective_rpc(worker_identity); its payload is the already reviewed fixed local worker_identity function that reads model class, parameter dtypes, counts and remote-module identities. It has no model-output dependence and loads no outside serialized payload. GLM follows the same code path; its exact attempt must be preserved on exit.

The installed native vLLM V1 serializer provides the process-local VLLM_ALLOW_INSECURE_SERIALIZATION=1 compatibility setting for this callable transport. A root-authorized retry adds that setting to the existing dedicated short local IPC path environment. This is limited to our owned front-end and engine processes; no global environment, system package, external endpoint, model/prompt/sampling/target/ordering/analysis rule is changed. The 269-file scientific freeze remains unchanged. Every failed attempt, GO and stdout must be retained before a new explicit root retry authorization. Independent static review and a local CPU round-trip of this exact frozen function are required first. No automatic retry is permitted.

Scope clarification before explicit retry: this setting enables general pickle/cloudpickle fallback for the process and its local children; it is not a single-function whitelist. The only planned callable is the fixed inspected worker_identity function, passed between our owned local processes. The independent CPU codec test establishes exact trustworthy-function round-trip, not a general security guarantee or successful GPU gate.
