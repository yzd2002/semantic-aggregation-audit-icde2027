# Pre-selection implementation details

These choices instantiate protocol v2 before selecting targets or observing new model judgments. All source labels are inverted for an actual second selection run. Labels are read by evaluation only after chosen feature IDs and prompt signatures are fixed. Original full feature strings are preserved; exclusion normalization uses casefold and collapsed whitespace only, without NFKC.

Features are compact UTF-8 JSON objects in source field order. Bibliographic fields are title, authors, venue, year for left then right; BoolQ fields are question then passage. A source ID contains the split and original row index (and left/right IDs for DBLP–ACM). Namespaced left/right IDs retain their original source roles, while normalized complete citation fingerprints are compared across roles. Full-feature deduplication keeps the first lexicographic source ID. The feature-length threshold is applied before reserve formation to target and training rows, with both local tokenizers and no truncation.

Targets use one Python Random(2026110201) stream in task order DBLP–ACM, BoolQ. Eligible DBLP left IDs begin lexicographically sorted, each pair list starts in source-ID order, and both are shuffled as specified. BoolQ begins in original row order before shuffling. Background proposals use a separate Random(2026110202) stream in the same task/reserve order. For each width 16, 32, 64, at most 2000 whole-triplet proposals are considered. At each position, uniformly choose one remaining eligible record, applying both tokenizer length tolerances and observed identity exclusions. An empty candidate set stops that width. Full prompted lengths and the context cap are tested after drawing a complete triplet. Similarity never determines acceptance of a random proposal. All proposals and feasibility failures are retained.

TF–IDF is implemented with NumPy/SciPy, because scikit-learn is absent. Unicode word regex is `(?u)\b\w+\b` (including single-character words), lowercased word unigrams and bigrams, raw term counts, smoothed IDF `log((1+N)/(1+df))+1`, and L2 normalization. The vocabulary and document frequencies are fitted on the eligible deduplicated training bank only. Near ranking uses cosine descending and source ID ascending on ties. Greedy within-triplet identity exclusion follows the protocol. The index parameters, vocabulary hash, IDF hash and bank IDs are saved.

One schedule is shuffled by Python Random(2026110203) after constructing task/selected-target/scope/context/repeat order. Scope construction order is full-first, target-only, full-last, singleton; contexts are near, random; repeats are 1, 2. Both models use identical request IDs, ordinals and blocks of at most 64.

The exact task instructions and record serialization live in common.py. Full-first/full-last prompts are byte-identical, and differ only in output grammar. Full-first/target-only have literal JSON output prefix `{"1":"` before the target decision. The target record is always input ID 1 and first. Prepared requests save its exact character and UTF-8 byte boundaries, wrapped prefix, and the token prefix whose token ends are at or before the target record end. Requested IDs are separate from grammar output order. Empty authors are preserved. No prompt, grammar, cap or target is selected using any model output.

Bootstrap uses NumPy default_rng(2026110204), reset independently for each task/model, with 4000 draws of n common12 target indices. Target order is selected_ordinal ascending. The same index matrix is shared across scopes, both paired scope contrasts and signed random-to-near error differences within that task/model. Percentiles use linear interpolation: 0.025/0.975 and, for full-first only, 0.00625/0.99375. Primary positive-evidence criterion is lower 98.75% endpoint > 0. Secondary contrasts are target-only minus full-first and full-last minus full-first. Gold flip direction is random to near: near-minus-random error equals right-to-wrong minus wrong-to-right. No statistical conclusion is selected using 95% intervals.

All contextual candidate comparisons use the common12 set; singleton comparisons use common14. Condition-specific quality retains its own valid set, with its denominator stated. COUNT always uses all selected targets, not common12 or an available-case denominator: any invalid/unreturned target makes that condition abstain. Fixed-relation contextual and replay comparisons require both complete conditions. Exact count, signed ratio/count change, absolute change, gold count error, and flip-versus-net cancellation are descriptive; they are distinct from mean per-target label disagreement.

The original global runtime is unchanged. The adapter files are copied verbatim from the previous completed experiment. The adapter only changes the checked vLLM singleton Gloo-group construction to real NCCL groups; its wrapped guards are not a universal guarantee about all future communication APIs. All synthetic diagnostics and ordinary/guided BANANA controls are counted and saved, and semantic success is not a gate for retaining either model or a task.
